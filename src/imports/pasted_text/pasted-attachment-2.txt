# NotchHR Authentication — Final Walkthrough & Visual Treatment

Update the **existing NotchHR authentication experience** using the authentication copy and flow already present in the project.

This is a **visual/layout refinement**, not a request to invent a new authentication system.

## 1. DO NOT CHANGE THE AUTHENTICATION FUNCTIONALITY

Maintain the existing:

* Authentication flow
* Phone number login
* PIN entry
* OTP verification
* Organisation selection
* Forgot PIN flow
* PIN reset flow
* Loading state
* Validation states
* Success state
* Existing interactions
* Existing dynamic data
* Existing authentication logic

Do not invent additional authentication steps.

Do not add:

* Username
* Email login
* Password login
* Remember me
* Sign up/register flow
* Terms/privacy links
* Biometric login
* Account-lock messaging
* Any other authentication functionality not already present.

The authentication copy inventory already provided by this project is the **source of truth**.

---

# 2. AUTHENTICATION LAYOUT

Keep the authentication experience as a **two-panel desktop composition**.

### Left side

This is the visual/product walkthrough area.

### Right side

This contains the actual authentication form.

Do **NOT** introduce a sidebar.

Do **NOT** turn this into a dashboard layout.

Do **NOT** add dashboard navigation.

Do **NOT** add a header or footer that does not belong to the authentication experience.

The authentication form should remain clean, spacious and highly usable.

---

# 3. WALKTHROUGH MUST HAVE 9 VISUAL SLIDES

The left-side walkthrough should contain **exactly 9 slides**.

The first slide is a special introductory/product slide.

The remaining 8 slides correspond exactly to the existing 8 feature messages already supplied in the authentication copy inventory.

Do not create additional feature messages.

Do not rewrite the supplied copy.

Do not invent statistics, benefits or product claims.

---

Create the first walkthrough slide as the **hero/introduction slide**.

Use the existing NotchHR brand/design system.

The visual treatment should communicate:

**NotchHR is an all-in-one HR platform for employees.**

The slide should visually introduce the employee experience before the feature slides begin.

Use:

* NotchHR branding
* Existing brand colours
* Existing typography
* Existing visual language
* A polished employee-at-work illustration
* Subtle supporting UI/product visual elements where appropriate

The illustration should feel like a real NotchHR product illustration rather than a generic stock illustration.

Show employees interacting with work/HR-related activities.

The composition should feel similar in quality to the existing NotchHR authentication design language.

Do not introduce a new design system.

# 6. ILLUSTRATION STYLE

The illustrations are important.

Do not simply place an icon beside each feature.

Each slide should feel like a **small visual story of an employee using NotchHR**.

The illustrations should:

* Represent employees at work
* Reflect African/modern workplace diversity
* Feel professional and enterprise-ready
* Match NotchHR's existing visual language
* Use the existing NotchHR colour system
* Feel polished and intentional
* Work naturally inside the available left-panel space
* Have consistent visual quality across all 9 slides

Do not make the illustrations photographic.

Do not make them generic stock imagery.

Do not use unrelated decorative imagery.

---

# 7. IMPORTANT — DO NOT STRETCH THE VISUALS

The walkthrough visuals must be treated as **contained visual compositions**, not as giant full-width cards.

Do not stretch an illustration to fill the entire left panel.

Do not distort or squash illustrations.

Do not crop important parts of an illustration.

Do not create a giant image with a huge empty area around it.

The illustration should retain its intended proportions and sit naturally within the composition.

Use a subtle background/masked visual area where necessary so the illustration feels like a designed product asset.

The result should feel like:

**illustration + copy + ambient information**

rather than:

**giant stretched image + text.**
